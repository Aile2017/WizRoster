# WizRoster

UCSD p-System 版 Wizardry #1 のキャラクタ編集ツール(Windows / C# WinForms / .NET 10)。
ディスクイメージの `SCENARIO.DATA` からキャラクタ 20 人分とマスタデータ(アイテム・呪文)を読み、編集して書き戻す。

## 使い方

```
dotnet run --project src/WizRoster -- <イメージのパス>
```

- ファイルはドラッグ&ドロップでも開ける。
- 上書き保存すると、元のファイルを `<名前>.bak_yyyyMMdd_HHmmss` に残してから書き込む。
- エミュレータがイメージを開いている間は保存しないこと。

## 対応イメージ

| 機種 | 形式 | 状態 |
|---|---|---|
| PC-98 | FDI(ヘッダ + シリンダ 0 を飛ばしたブロック) | 確認済み |
| Apple II | 140KB DOS 3.3 順 `.dsk`(シナリオディスク 2 枚目) | 読み込み確認済み |
| PC-DOS / MSX2 | 生イメージ(ディレクトリから先頭を逆算) | 未確認 |
| PC-8801 | D88 | 未対応 |

形式の判別は `ImageLoader` が行う。新しい形式は `IBlockImage`(512 バイトブロックの読み書き)を実装して候補に足す。

## データの位置の求め方

`SCENARIO.DATA` 先頭の目次(TSCNTOC)を使うので、機種ごとの固定オフセットは持たない。

| 位置 | 内容 |
|---|---|
| +0 | シナリオ名 STRING[40] |
| +42 | RECPER2B[8]: 1024 バイトあたりの件数 |
| +58 | RECPERDK[8]: 件数 |
| +90 | BLOFF[8]: 開始ブロック(4 = アイテム, 5 = キャラクタ) |

- キャラクタ i: `BLOFF[5]*512 + (i / 4) * 1024 + (i % 4) * 208`
- アイテム n: `BLOFF[4]*512 + (n / 13) * 1024 + (n % 13) * 78`
- 呪文名: 迷宮データ(`BLOFF[1]`)の 2 ブロック前が魔術師、1 ブロック前が僧侶。0Dh 区切りで、レベルの区切りに `*`。

キャラクタ(208 バイト)とアイテム(78 バイト)の項目は `Character.cs` と `ItemDef.cs` を参照。

## 構成

- `src/WizRoster.Core`: イメージ・UCSD ディレクトリ・シナリオ・キャラクタの読み書き(GUI に依存しない)
- `src/WizRoster`: WinForms の画面
- `tests/WizRoster.Tests`: xUnit。実イメージがあればそれを使って確かめる(環境変数 `WIZROSTER_PC98` / `WIZROSTER_APPLE2` で場所を変えられる)
