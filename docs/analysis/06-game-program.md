# 06. ゲーム本体(p-code)の解析

セービングスローや毒の扱いは、データを眺めるだけでは分からないので、ゲーム本体を逆アセンブルして確かめた。
対象は Apple II 版 #1〜#3 の `WIZARDRY.CODE` と、PC-98 版 #1 の `SYSTEM.PASCAL`。
どちらも UCSD p-System II 系(Apple Pascal 1.1 相当)の p-code で、同じ方法で読める。
使ったスクリプトは `tools/pcode/`。

## 1. コードファイルの形式

- ブロック 0 がセグメント辞書: +0 から 16 件の (開始ブロック, 長さ[バイト])、+64 から 16 件の名前(8 文字)。
- セグメントの末尾: 最後のワードが (セグメント番号, 手続きの数)。その前に、各手続きの属性表への自己相対ポインタが並ぶ。
  属性表は (手続き番号, レキシカルレベル)、その前のワードが入口、さらに前が出口(どちらも自己相対)。

セグメント(Apple II 版 #1):

| セグメント | 推測される役割 |
|---|---|
| WIZARDRY | 本体(共通の手続き) |
| UTILITIE | 共通の処理(セービングスローの計算など) |
| SHOPS | 城の施設(全滅の処理もここ) |
| SPECIALS | 迷宮の特殊な場所 |
| COMBAT / CINIT / CUTIL / MELEE | 戦闘 |
| CASTASPE | 呪文を唱える |
| SWINGASW | 攻撃(敵の打撃・ブレス) |
| CASTLE | 城 |
| ROLLER | キャラクタの作成 |
| CAMP | キャンプ |
| REWARDS | 戦闘後の宝箱・経験値 |
| RUNNER | 迷宮の移動 |

PC-98 版は、これに KANJIREA(漢字の読み込み)と GAMEUTIL が加わり、並び順が少し違う。
文字列は `ASCII.KRN` のメッセージ番号(`LDCI 番号`)で出すので、逆アセンブルに文字列は出ない。

## 2. 探し方

キャラクタはグローバルの配列(`LAO 74`、1 人 104 ワード)。項目の読み書きは、レコードの先頭から
`INC n`(n ワード進む)や `IND n`(n ワード目を読む)で行う。5 ビット詰めの配列は `IXP 3 5`(1 ワードに 3 つ、5 ビット)で要素を指す。

| 調べたいもの | 探した命令の並び |
|---|---|
| セービングスロー(+48 = 24 ワード目) | `INC 24 ; (番号) ; IXP 3 5 ; LDP`(読む)/ `… ; STP`(書く) |
| 能力値(+44 = 22 ワード目) | `INC 22 ; (番号) ; IXP 3 5` |
| 毒・置き去りの位置(+200 = 100 ワード目) | `INC 100` / `IND 100` |

主な命令(II 系): `SLDC n`(定数、0〜127)、`SLDL n` / `LDL n`(ローカル変数)、`LAO n`(グローバルの番地)、
`IXA n`(n ワードの要素の配列の添字)、`INC n` / `IND n`、`IXP a b`、`LDP` / `STP`、`CIP` / `CLP` / `CXP`(手続きの呼び出し)、
`XJP`(表によるジャンプ。case 文)、`FJP`(偽なら飛ぶ)、`CSP 4`(EXIT)。

## 3. 分かったこと

### 3.1 セービングスロー(+48)

| 手続き(Apple II #1 / PC-98 #1) | 処理 |
|---|---|
| SWINGASW p11 / p14 | 汎用の判定。引数は (効果, 使うセービングスローの番号, 抵抗ビット, メッセージ)。`乱数 mod 20 > 値` なら避ける。+196 の抵抗ビットが立っていても避ける。状態が死亡以上なら何もしない |
| SWINGASW p9 / (同) | 敵の打撃の追加効果。上の汎用の判定を 4 通りに呼ぶ(下の表) |
| SWINGASW p6 / CASTASPE p32 | ブレス(`BREATHES!`)。ダメージ = 敵の HP ÷ 2。`乱数 mod 20 ≥ 4 番目の値` なら半減。抵抗ビットでさらに半減 |
| CASTASPE p10 / なし | 敵の沈黙の呪文をパーティーが受けたとき。避ける確率 = 100 − 5 × 5 番目の値(%)。PC-98 版にはこの処理がない(沈黙はこちらが敵にかけるものだけ) |
| REWARDS p12 / p14 | 宝箱の罠。ガス爆弾は全員に 4 番目で判定し、失敗すると毒の量 +1 |
| REWARDS p14 / p16 | 宝箱の罠(職業で分岐するもの)。5 番目で判定 |
| UTILITIE p25 / p15 | 値の計算(下の式) |
| UTILITIE p35 / p27 | 1 つの値から引く(1 未満にしない) |
| ROLLER p10 / − | キャラクタ作成時に 5 つとも 16 にする |

汎用の判定の呼び出し(#1〜#3、Apple II・PC-98 で同じ):

| メッセージ | 効果 | 使う番号(0 から) | 抵抗ビット | 失敗したとき |
|---|---:|---:|---:|---|
| POISONED | 1 | 0 | 3 | 毒の量(+200)を 1 にする |
| PARALYZED | 2 | 0 | 0(なし) | 状態を 3(麻痺)にする |
| STONED | 0 | 1 | 5 | 状態を 4(石化)にする |
| CRITICALLY HIT | 3 | 0 | 0(なし) | 状態を 5(死亡)、HP を 0 にする |

まとめると、5 つのセービングスローの用途は次のとおり。3 番目はどの判定にも使われていない(#1〜#3 とも)。

| 番号 | 用途 | 避ける条件(r = 0〜19 の乱数) | 値 1 で避ける確率 | 値 19 で避ける確率 |
|---|---|---|---:|---:|
| 1 | 毒・麻痺・クリティカル(即死) | r > 値 | 90% | 0% |
| 2 | 石化 | r > 値 | 90% | 0% |
| 3 | (使われない) | − | − | − |
| 4 | ブレス(半減)、ガス爆弾 | r ≥ 値 | 95% | 5% |
| 5 | 呪文(Apple II 版の沈黙)、職業別の罠 | 沈黙: 100 − 5 × 値 % | 95% | 5% |

値の計算(UTILITIE p25 / p15):

1. 基本値 = 20 − レベル ÷ 5 − 運 ÷ 6(1 未満なら 1)。5 つすべてに入れる。
2. 職業で引く(case 0〜7): 戦士 1 番目 −3 / 魔術師 5 番目 −3 / 僧侶 2 番目 −3 / 盗賊 4 番目 −3 /
   司教 3・5・2 番目 −2 / 侍 1・5 番目 −2 / 君主 1・2 番目 −2 / 忍者 1 番目 −3・2 番目 −2・3 番目 −4・4 番目 −3・5 番目 −2
3. 種族で引く(case 1〜5): 人間 1 番目 −1 / エルフ 3 番目 −2 / ドワーフ 4 番目 −4 / ノーム 2 番目 −2 / ホビット 5 番目 −3
4. どれも 1 未満にはしない。

実際のキャラクタの値と一致した(T1: 盗賊・人間・Lv1 → 18, 19, 19, 16, 19。GUYDOMAN: 戦士・ドワーフ・Lv12 → 15, 18, 18, 14, 18 など 7 人)。
PC-98 版は、汎用の判定の引数、補正の表、基本値の式がすべて Apple II 版と同じだった。

### 3.2 毒と置き去り(+200〜+206)

`INC 100` / `IND 100` を使う箇所(Apple II 版 #1):

| 手続き | 処理 |
|---|---|
| SWINGASW p11 | 毒を受けたとき +200 を 1 にする |
| REWARDS p12 | ガス爆弾: +200 に 1 を足す |
| RUNNER p28 | 迷宮を 1 歩ごとに HP = HP − 毒の量 + HEALPTS(+178)。0 以下で死亡し、毒を 0 にする |
| CASTLE p3、CAMP p32 | +200 が 0 でなければ状態の欄に `POISON` と表示する |
| CASTASPE p27、CAMP p6・p11 | 治療(`IS UNPOISONED!`、`CURED`)で 0 にする |
| CAMP p33 | キャンプからの中断: 各メンバーの INMAZE を 0、+200・+202・+204 に今の X・Y・階、年齢に 25 週を足してディスクに書く |
| SHOPS p24(p21 の `YOUR ENTIRE PARTY HAS BEEN SLAUGHTERED` から) | 全滅: 状態を死亡にし、死んだ場所を +200〜+204 に書く。一定の確率で −1, −1, −1(行方不明) |
| SPECIALS p5 | 迷宮でキャラクタを拾う(`GET WHO`): +200〜+204 を 0 にする |
| CASTLE p9 | 酒場: INMAZE が真か +204 が 0 でなければ `** OUT **` |
| SHOPS p30、CAMP p29・p30 | +206 の称号のビット(クリアの印)の設定と表示 |

## 4. 未解析のこと

- アスキー移植版のうち、PC-98 以外(PC-DOS・MSX2・PC-8801)は逆アセンブルしていない(PC-98 と同じと考えている)。
- ゲームがセービングスローや AC を計算し直す場面(宿屋でのレベルアップ、装備の変更など)は追っていない。
- 置き去りにしたパーティーで再開するときの処理は追っていない。
- #3 の持ち物の番号に 1000 を足す処理は探していない。
