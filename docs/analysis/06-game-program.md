# 06. ゲーム本体(p-code)の解析

セービングスローや毒の扱いは、データを眺めるだけでは分からないので、ゲーム本体を逆アセンブルして確かめた。
対象は Apple II 版 #1〜#3 の `WIZARDRY.CODE` と、PC-98 版 #1 の `SYSTEM.PASCAL`。
どちらも UCSD p-System II 系(Apple Pascal 1.1 相当)の p-code で、同じ方法で読める。
使ったスクリプトは `tools/pcode/`。

## 1. コードファイルの形式

- ブロック 0 がセグメント辞書: +0 から 16 件の (開始ブロック, 長さ[バイト])、+64 から 16 件の名前(8 文字)。
- セグメントの末尾: 最後のワードが (セグメント番号, 手続きの数)。その前に、各手続きの属性表への自己相対ポインタが並ぶ。
  属性表は (手続き番号, レキシカルレベル)、その前のワードが入口、さらに前が出口(どちらも自己相対)。

セグメント(Apple II 版 #1):

| セグメント | 推測される役割 |
|---|---|
| WIZARDRY | 本体(共通の手続き) |
| UTILITIE | 共通の処理(セービングスローの計算など) |
| SHOPS | 城の施設(全滅の処理もここ) |
| SPECIALS | 迷宮の特殊な場所 |
| COMBAT / CINIT / CUTIL / MELEE | 戦闘 |
| CASTASPE | 呪文を唱える |
| SWINGASW | 攻撃(敵の打撃・ブレス) |
| CASTLE | 城 |
| ROLLER | キャラクタの作成 |
| CAMP | キャンプ |
| REWARDS | 戦闘後の宝箱・経験値 |
| RUNNER | 迷宮の移動 |

PC-98 版は、これに KANJIREA(漢字の読み込み)と GAMEUTIL が加わり、並び順が少し違う。
文字列は `ASCII.KRN` のメッセージ番号(`LDCI 番号`)で出すので、逆アセンブルに文字列は出ない。

## 2. 探し方

キャラクタはグローバルの配列(`LAO 74`、1 人 104 ワード)。項目の読み書きは、レコードの先頭から
`INC n`(n ワード進む)や `IND n`(n ワード目を読む)で行う。5 ビット詰めの配列は `IXP 3 5`(1 ワードに 3 つ、5 ビット)で要素を指す。

| 調べたいもの | 探した命令の並び |
|---|---|
| セービングスロー(+48 = 24 ワード目) | `INC 24 ; (番号) ; IXP 3 5 ; LDP`(読む)/ `… ; STP`(書く) |
| 能力値(+44 = 22 ワード目) | `INC 22 ; (番号) ; IXP 3 5` |
| 毒・置き去りの位置(+200 = 100 ワード目) | `INC 100` / `IND 100` |

主な命令(II 系): `SLDC n`(定数、0〜127)、`SLDL n` / `LDL n`(ローカル変数)、`LAO n`(グローバルの番地)、
`IXA n`(n ワードの要素の配列の添字)、`INC n` / `IND n`、`IXP a b`、`LDP` / `STP`、`CIP` / `CLP` / `CXP`(手続きの呼び出し)、
`XJP`(表によるジャンプ。case 文)、`FJP`(偽なら飛ぶ)、`CSP 4`(EXIT)。

## 3. 分かったこと

### 3.1 セービングスロー(+48)

| 手続き(Apple II #1 / PC-98 #1) | 処理 |
|---|---|
| SWINGASW p11 / p14 | 汎用の判定。引数は (効果, 使うセービングスローの番号, 抵抗ビット, メッセージ)。`乱数 mod 20 > 値` なら避ける。+196 の抵抗ビットが立っていても避ける。状態が死亡以上なら何もしない |
| SWINGASW p9 / (同) | 敵の打撃の追加効果。上の汎用の判定を 4 通りに呼ぶ(下の表) |
| SWINGASW p6 / CASTASPE p32 | ブレス(`BREATHES!`)。ダメージ = 敵の HP ÷ 2。`乱数 mod 20 ≥ 4 番目の値` なら半減。抵抗ビットでさらに半減 |
| CASTASPE p10 / なし | 敵の沈黙の呪文をパーティーが受けたとき。避ける確率 = 100 − 5 × 5 番目の値(%)。PC-98 版にはこの処理がない(沈黙はこちらが敵にかけるものだけ) |
| REWARDS p12 / p14 | 宝箱の罠。ガス爆弾は全員に 4 番目で判定し、失敗すると毒の量 +1 |
| REWARDS p14 / p16 | 宝箱の罠(職業で分岐するもの)。5 番目で判定 |
| UTILITIE p25 / p15 | 値の計算(下の式) |
| UTILITIE p35 / p27 | 1 つの値から引く(1 未満にしない) |
| ROLLER p10 / − | キャラクタ作成時に 5 つとも 16 にする |

汎用の判定の呼び出し(#1〜#3、Apple II・PC-98 で同じ):

| メッセージ | 効果 | 使う番号(0 から) | 抵抗ビット | 失敗したとき |
|---|---:|---:|---:|---|
| POISONED | 1 | 0 | 3 | 毒の量(+200)を 1 にする |
| PARALYZED | 2 | 0 | 0(なし) | 状態を 3(麻痺)にする |
| STONED | 0 | 1 | 5 | 状態を 4(石化)にする |
| CRITICALLY HIT | 3 | 0 | 0(なし) | 状態を 5(死亡)、HP を 0 にする |

まとめると、5 つのセービングスローの用途は次のとおり。3 番目はどの判定にも使われていない(#1〜#3 とも)。

| 番号 | 用途 | 避ける条件(r = 0〜19 の乱数) | 値 1 で避ける確率 | 値 19 で避ける確率 |
|---|---|---|---:|---:|
| 1 | 毒・麻痺・クリティカル(即死) | r > 値 | 90% | 0% |
| 2 | 石化 | r > 値 | 90% | 0% |
| 3 | (使われない) | − | − | − |
| 4 | ブレス(半減)、ガス爆弾 | r ≥ 値 | 95% | 5% |
| 5 | 呪文(Apple II 版の沈黙)、職業別の罠 | 沈黙: 100 − 5 × 値 % | 95% | 5% |

値の計算(UTILITIE p25 / p15):

1. 基本値 = 20 − レベル ÷ 5 − 運 ÷ 6(1 未満なら 1)。5 つすべてに入れる。
2. 職業で引く(case 0〜7): 戦士 1 番目 −3 / 魔術師 5 番目 −3 / 僧侶 2 番目 −3 / 盗賊 4 番目 −3 /
   司教 3・5・2 番目 −2 / 侍 1・5 番目 −2 / 君主 1・2 番目 −2 / 忍者 1 番目 −3・2 番目 −2・3 番目 −4・4 番目 −3・5 番目 −2
3. 種族で引く(case 1〜5): 人間 1 番目 −1 / エルフ 3 番目 −2 / ドワーフ 4 番目 −4 / ノーム 2 番目 −2 / ホビット 5 番目 −3
4. どれも 1 未満にはしない。

実際のキャラクタの値と一致した(T1: 盗賊・人間・Lv1 → 18, 19, 19, 16, 19。GUYDOMAN: 戦士・ドワーフ・Lv12 → 15, 18, 18, 14, 18 など 7 人)。
PC-98 版は、汎用の判定の引数、補正の表、基本値の式がすべて Apple II 版と同じだった。

### 3.2 毒と置き去り(+200〜+206)

`INC 100` / `IND 100` を使う箇所(Apple II 版 #1):

| 手続き | 処理 |
|---|---|
| SWINGASW p11 | 毒を受けたとき +200 を 1 にする |
| REWARDS p12 | ガス爆弾: +200 に 1 を足す |
| RUNNER p28 | 迷宮を 1 歩ごとに HP = HP − 毒の量 + HEALPTS(+178)。0 以下で死亡し、毒を 0 にする |
| CASTLE p3、CAMP p32 | +200 が 0 でなければ状態の欄に `POISON` と表示する |
| CASTASPE p27、CAMP p6・p11 | 治療(`IS UNPOISONED!`、`CURED`)で 0 にする |
| CAMP p33 | キャンプからの中断: 各メンバーの INMAZE を 0、+200・+202・+204 に今の X・Y・階、年齢に 25 週を足してディスクに書く |
| SHOPS p24(p21 の `YOUR ENTIRE PARTY HAS BEEN SLAUGHTERED` から) | 全滅: 状態を死亡にし、死んだ場所を +200〜+204 に書く。一定の確率で −1, −1, −1(行方不明) |
| SPECIALS p5 | 迷宮でキャラクタを拾う(`GET WHO`): +200〜+204 を 0 にする |
| CASTLE p9 | 酒場: INMAZE が真か +204 が 0 でなければ `** OUT **` |
| SHOPS p30、CAMP p29・p30 | +206 の称号のビット(クリアの印)の設定と表示 |

### 3.3 呪文の回数(+146 MAGESP・+160 PRIESTSP)

城のセグメントで計算し直す(Apple II 版 #1)。回数は覚えている呪文とレベルから毎回作り直すので、回数だけ書き換えても効かない([07-verification.md](07-verification.md))。

| 手続き | 処理 |
|---|---|
| CASTLE p18 | 全体。p24・p23 を呼んだあと、職業(+36)で分岐して p20・p21 を呼ぶ |
| CASTLE p23 / p24 | 魔術師 / 僧侶の各段の回数を、その段で覚えている呪文の数にする(p22 が呪文番号の範囲のビットを数える) |
| CASTLE p21 / p20 | 魔術師 / 僧侶の回数に、レベルによる回数を当てはめる(どちらも p19 を呼ぶ) |
| CASTLE p19 | レベルによる回数。引数は (開始, 間隔) |

p18 は CASTLE p26(レベルアップ。3.4)・p28・p35 から呼ばれる。

段ごとの呪文番号の範囲: 魔術師 1〜4・5〜6・7〜8・9〜11・12〜14・15〜18・19〜21、
僧侶 22〜26・27〜30・31〜34・35〜38・39〜44・45〜48・49〜50。

計算(p19):

1. 1 段目から順に `n = レベル − 開始 − (段 − 1) × 間隔` を求め、n が 0 より大きく今の回数より大きければ n にする(n が 0 以下になったら打ち切り)。
2. 最後に 1〜7 段のどれも 9 を超えないようにする。

つまり各段の回数は「覚えている数」と「レベルから出す数」の多いほうで、9 が上限。
低いレベルでも、覚えている呪文の数だけは使える(例: レベル 1 の魔術師に全呪文を覚えさせると、7 段目は 3 回)。

| 職業 | 系統 | 開始 | 間隔 | 7 段目が 1 回になるレベル | 7 段目が 9 回(全段 9 回)になるレベル |
|---|---|---:|---:|---:|---:|
| 魔術師 | 魔術師 | 0 | 2 | 13 | 21 |
| 僧侶 | 僧侶 | 0 | 2 | 13 | 21 |
| 司教 | 魔術師 | 0 | 4 | 25 | 33 |
| 司教 | 僧侶 | 3 | 4 | 28 | 36 |
| 侍 | 魔術師 | 3 | 3 | 22 | 30 |
| 君主 | 僧侶 | 3 | 2 | 16 | 24 |

7 段目が 9 回になるレベルは `9 + 開始 + 6 × 間隔`。
戦士・盗賊・忍者はレベルによる回数がないが、p23・p24 は全職業に行うので、覚えている呪文があればその数だけ回数がつくはず(ゲームでは試していない)。
PC-98 版など、ほかの機種・シナリオでは確かめていない。

### 3.4 レベルアップと最大 HP(+136 HPMAX)

| 手続き | 処理 |
|---|---|
| CASTLE p26 | レベルアップ(`YOU MADE A LEVEL!`)。レベル(+132)を 1 上げ、最高レベル(+130)より大きければ合わせる。p18(呪文の回数)を呼ぶ。最大 HP を計算し直す |
| CASTLE p27 | 1 レベル分の HP |

1 レベル分の HP(p27) = 職業のダイス + 生命力(能力値の 4 番目)の補正。1 未満なら 1。

| 職業 | ダイス |
|---|---|
| 戦士・君主 | 1〜10 |
| 僧侶・侍 | 1〜8 |
| 盗賊・司教・忍者 | 1〜6 |
| 魔術師 | 1〜4 |

| 生命力 | 3 | 4〜5 | 6〜15 | 16 | 17 | 18 |
|---|---:|---:|---:|---:|---:|---:|
| 補正 | −2 | −1 | 0 | +1 | +2 | +3 |

最大 HP(p26):

1. 新しいレベルの数だけ p27 を呼んで合計する(1 レベル分ずつ足すのではなく、全部振り直す)。侍だけは 1 回多く呼ぶ。
2. 合計が今の最大 HP 以下なら、最大 HP + 1 にする。最大 HP が下がることはなく、レベルアップのたびに 1 以上増える。

振り直しが下回ったときも +1 で残るので、最大 HP は平均(レベル × 1 レベル分の平均)より少し高めに寄る。
レベル 36 の目安(レベル 1 の HP を 1 レベル分として、上の手順を 2 万回試した平均。カッコ内は下位 10%〜上位 10%):

| 職業 | 生命力 6〜15 | 生命力 18 |
|---|---:|---:|
| 戦士・君主 | 211(197〜226) | 315(300〜332) |
| 侍 | 177(166〜189) | 285(272〜298) |
| 僧侶 | 172(161〜184) | 277(264〜290) |
| 盗賊・司教・忍者 | 134(126〜143) | 239(229〜249) |
| 魔術師 | 95(90〜101) | 200(194〜207) |

キャラクタ作成時の最初の HP(ROLLER)と、転職したときの HP は追っていない。

### 3.5 戦闘の能力(+174〜+198)

UTILITIE p25(セービングスローと同じ手続き)が、職業・レベル・力から初期値を入れ、持ち物と装備の分を足す。
p25 は装備の処理そのもので、引数が偽のときは装備をすべて外して種類ごとに選ばせ(p32、`SELECT WEAPON FOR` など)、
真のときは今の装備のまま計算し直す(p31)。
そのため、エディタで持ち物や装備を変えても、この節の値とセービングスローは古いまま残る。ゲームで装備し直すと計算し直される。
アイテムのレコード(TOBJREC)は p26・p29・p30 で読み、`LDA 16` からの 39 ワードに置く(`LOD 32` = 種類、`LOD 33` = 属性、
`LOD 43` = 装備できる職業、`LOD 44` = HEALPTS、`LDA 45` = 防御の対象、`LDA 46` = 抵抗、`LOD 47` = AC 補正、`LOD 48` = 命中補正、
`LDA 49` = ダメージ 3 ワード、`LOD 52` = 攻撃回数、`LOD 53` = クリティカル、`LDA 54` = 倍打の対象)。

初期値(p25。力は能力値の 1 番目):

| 項目 | 初期値 |
|---|---|
| +174 命中の補正 | 戦士・僧侶・侍・君主・忍者は 2 + レベル ÷ 3、魔術師・盗賊・司教はレベル ÷ 5。力 16 以上なら + (力 − 15)、力 5 以下なら + (力 − 6) |
| +176 AC | 10 |
| +178 HP 回復量 | 0 |
| +180 クリティカル | 忍者だけ真 |
| +182 攻撃回数 | 1。戦士・侍・君主・忍者は + レベル ÷ 5、忍者はさらに + 1。10 を超えたら 10 |
| +184〜+188 ダメージ | 2d2 + 0(忍者は 2d4)。力 16 以上なら加算 = 力 − 15 |
| +190〜+198 | 0(p36 で消す) |

持ち物(p29。装備していなくても、持っているだけで効く):

- +178 = 持ち物の HEALPTS の最大値(足し算ではない)。
- +190 に防御の対象、+194 に抵抗のビットを OR する。

装備(p31 が装備している品ごとに p30 を呼ぶ):

- アイテムの属性が 0 か、キャラクタの属性と同じとき:
  - 攻撃回数 = 今の値とアイテムの値の大きいほう
  - AC −= AC 補正、命中の補正 += 命中補正
  - 武器(種類 0)なら: ダメージ = 武器の値(加算には力の分を足す)、クリティカル |= 武器の値、+198 = 武器の倍打の対象
- 属性が合わないとき: 命中の補正 − 1、AC + 1、クリティカルを消し、その品を呪われた状態にする。
- 忍者は、装備がひとつもなければ最後に AC −= レベル ÷ 3 + 2。

戦闘での使い方:

| 項目 | 手続き | 使い方 |
|---|---|---|
| +174 | SWINGASW p15 | 命中に必要な値 = 21 − 敵の値 − 命中の補正 + 敵の AC − 3 × 隊列(1〜19 に収める)。0〜19 の乱数がこれ以上なら当たる |
| +182 | SWINGASW p15 | 1 回の攻撃でこの回数だけ命中の判定をする |
| +184 | SWINGASW p15 | 当たるたびにダイスを振る。敵が眠っていれば 2 倍 |
| +198 | SWINGASW p15 | 敵の種類のビットが立っていればダメージ 2 倍(倍打) |
| +180 | SWINGASW p15 | 真でダメージが 0 より大きいとき、確率 min(レベル × 2, 50)% で判定し、0〜34 の乱数が敵の値 + 10 より大きければ首をはねる |
| +190 / +192 | CINIT p8、CUTIL p20・p21 | 戦闘の始めに +190 を +192 に写す。+192 に敵の種類のビットが立っていると、その敵の行動が 50% で取りやめになる(CUTIL p21) |
| +194 / +196 | CINIT p8、SWINGASW p6・p10・p11 | 戦闘の始めに +194 を +196 に写す。+196 のビットで抵抗(3.1。ビット 4 = レベル吸収を防ぐ) |

### 3.6 ボルタック商店の在庫(アイテムの BOLTACXX)

SHOPS セグメント(Apple II 版 #1)。アイテムのレコードは `LDA 3` からの 39 ワードに読み、在庫数は `LOD 28`(25 ワード目 = +50)。

| 手続き | 処理 |
|---|---|
| SHOPS p13 / p14 | 品物の一覧。在庫が 0 以外で、呪われていない(`LOD 21`)品だけを出す |
| SHOPS p15 | 購入(`PURCHASE WHICH ITEM`)。在庫が 0 なら `YOU BOUGHT THE LAST ONE`。買えたら在庫が 0 より大きいときだけ 1 減らし、レコードを SCENARIO.DATA に書き戻す |
| SHOPS p19 | 売却・呪いを解く・鑑定。売却のときだけ、在庫が −1 より大きければ 1 増やして書き戻す |

- 在庫 −1 は無限(増えも減りもしない)。0 は店に並ばない。
- 在庫は SCENARIO.DATA のアイテム表にあるので、ディスクごとに持つ(キャラクタと同じディスクに書かれる)。

## 4. 未解析のこと

- アスキー移植版のうち、PC-98 以外(PC-DOS・MSX2・PC-8801)は逆アセンブルしていない(PC-98 と同じと考えている)。
- UTILITIE p25 を「装備を選ばせない」(引数が真)で呼ぶ場面(レベルアップなど)は追っていない。レベルアップ(CASTLE p26)で呼ぶ p28・p32 は中身を見ていない。
- 防御の対象(+192)で取りやめになる敵の行動が何か(CUTIL p20 の細部)、命中の式の「敵の値」が敵のどの項目かは確かめていない。
- 置き去りにしたパーティーで再開するときの処理は追っていない。
- #3 の持ち物の番号に 1000 を足す処理は探していない。
