# 02. SCENARIO.DATA

キャラクタ・アイテム・呪文名・経験値の表などは、すべて `SCENARIO.DATA` に入っている。
ファイルの先頭ブロックの目次(Wizardry のソースの型名は TSCNTOC)から各データの位置を求めるので、
機種ごとの固定の位置は持たなくてよい。

## 1. 目次(先頭ブロック)

| 位置 | 内容 | 確かさ |
|---|---|---|
| +0 | シナリオ名 STRING[40] | 確認(データ)。アスキー移植版の #1 は書き換わっている(`1031B` など) |
| +42 | RECPER2B[8]: 1024 バイトあたりの件数 | 確認(データ) |
| +58 | RECPERDK[8]: 件数 | 確認(データ) |
| +74 | UNUSEDXX[8]: 名前なしアイテムの版では 1 件のバイト数(下を参照)。それ以外では意味不明 | 確認(データ) |
| +90 | BLOFF[8]: ファイル先頭からの開始ブロック | 確認(データ) |
| +106 | 種族名 STRING[9] × 6 | 確認(データ) |
| +166 | 職業名 STRING[9] × 8 | 確認(データ) |
| +246 | 状態名 STRING[9] × 8 | 確認(データ) |
| +326 | 属性名 STRING[9] × 4 | 確認(データ)。アスキー移植版の #1 は壊れている |

配列の添字(区分。ソースの型名は TZSCN):

| 添字 | 区分 | 1 件の大きさ |
|---:|---|---|
| 0 | ZZERO(目次) | − |
| 1 | ZMAZE(迷宮) | − |
| 2 | ZENEMY(モンスター) | − |
| 3 | ZREWARD(宝) | − |
| 4 | ZOBJECT(アイテム) | 78 バイト(名前なしの版は 46 バイト) |
| 5 | ZCHAR(キャラクタ) | 208 バイト |
| 6 | ZSPCCHRS(特殊キャラクタ?) | − |
| 7 | ZEXP(経験値の表) | 624 バイト |

## 2. レコードの位置

区分 z の i 番目のレコードは、

```
BLOFF[z] × 512 + (i ÷ RECPER2B[z]) × 1024 + (i mod RECPER2B[z]) × 1 件の大きさ
```

- レコードは 1024 バイトの区切りをまたがない。区切りの残り(キャラクタなら 1024 − 4 × 208 = 192 バイト)には、古いデータが残っていることがある。
- キャラクタは最大 20 人(RECPERDK[5] = 20)。1024 バイトに 4 人。
- 空きスロットは名前の長さが 0。中には `UNSETH` で始まる古い文字列が残っていることが多い。

## 3. 名前なしアイテムの版(46 バイト)

PC-DOS 版の #1〜#3、アスキー移植版の #2・#3 などは、アイテムのレコードに名前(32 バイト)がない。

- 見分け方: 目次の `UNUSEDXX[5]`(キャラクタ)が 208、`UNUSEDXX[4]`(アイテム)が 46 のとき。
  このとき UNUSEDXX は各区分の 1 件のバイト数になっている(例: PC-DOS 版 #1 は `6, 894, 94, 168, 46, 208, 0, 624`)。
- アイテム名は同じディスクの `ASCII.KRN` から読む([05-ascii-krn.md](05-ascii-krn.md))。
- 名前以外は 78 バイトの版と同じ並び。PC-DOS 版 #1 と PC-98 版 #1 を番号ごとに比べると、101 件中 97 件が完全に一致し、違いはボルタック商店の在庫数だけだった。

## 4. 呪文名の表

- 0Dh 区切りの英大文字の名前。2 つ目以降のレベルの先頭に `*` が付く(`ASCII.KRN` の版は 1 つ目にも付く)。
- 魔術師の表と僧侶の表が、続いた 2 ブロックにある。

| 版 | 場所 |
|---|---|
| #1・#2 の多く | 迷宮データ(BLOFF[1])の 2 ブロック前が魔術師、1 ブロック前が僧侶 |
| Apple II 版 #3 | 目次の直後(1・2 ブロック目)。BLOFF の並び順が違う(迷宮が 55 ブロック目)ため、上の規則が当てはまらない |
| アイテム名のない版 | ディスク上に表はなく、`ASCII.KRN` の 5001〜5050 番から読む |

- MSX2 版 #1 の User Disk と PC-8801 版 #1 は、表が壊れている(空の行がある)。`ASCII.KRN` から読む。
- 呪文の番号(キャラクタの「覚えている呪文」のビット、アイテムの SPELLPWR)は、魔術師が 1 から、続けて僧侶(#1〜#3 では魔術師 1〜21、僧侶 22〜50)。

## 5. 経験値の表(区分 7)

8 職業 × 13 個の TWIZLONG(6 バイト。3 ワードの 10000 進数、下位ワードが先頭)。

- [1]〜[12]: レベル 2〜13 になるのに必要な経験値(累計)
- [0]: レベル 14 以降、1 レベル上がるごとに必要な経験値の増分
- レベル L(14 以上)に必要な経験値 = [12] + (L − 13) × [0]

Apple II 版 #1 と PC-DOS 版 #2 で同じ値だった。普通に育てたキャラクタは、全員このレベルと経験値の関係に合っていた(確認(データ))。

## 6. 種族・職業・状態・属性の名前

目次(+106 から)に英語名がある。アスキー移植版は `ASCII.KRN` にも入っている(10000 番台)。

| 値 | 種族 | 職業 | 状態(目次) | 状態(`ASCII.KRN`) | 属性 |

| 2 | ELF | PRIEST | ASLEEP | ASLEEP | NEUTRAL |

- アスキー移植版の #1(PC-98・PC-8801・MSX2)は、目次の属性名の欄が壊れている(`Æa-GN` など)。
- 状態に「毒」はない。毒はキャラクタの +200 で別に持つ([03-character-record.md](03-character-record.md))。

## 7. #2・#3 の違い

- 形式は #1 と同じ。アイテム数は #2 が 130、#3 が 104。キャラクタのレコード(208 バイト)も同じ。
- 呪文名・経験値の表・種族などの名前の場所も同じ(Apple II 版 #3 の呪文名の表だけ場所が違う)。
- #3 では、状態が「消滅」のキャラクタの持ち物の番号が「1000 + アイテム番号」になっていることがある。
  1000 を引いて #3 のアイテム表で引くと、職業と装備がそろう(例: 戦士 6502 = SALLET、HEATER+1、BREASTPLATE+1、BATTLE AXE+1、GLOVES OF IRON)。
  #1・#2 の表で引くと戦士が巻物を装備していることになり合わない。1000 を足す意味は不明。
